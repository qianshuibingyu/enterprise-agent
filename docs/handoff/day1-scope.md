## 1. 目标

- **【原始基线】** 建设部署在 Linux 服务器上的企业内部业务协作系统，收集客户通过已接入渠道联系公司的消息，由 Agent 辅助运营处理，并提供内部工作台、消息处理、知识检索、回复审核、询盘转交及业务链路信息展示。系统不提供面向网站访客的 AI 对话入口。来源：[`PROJECT_SPEC.md §1`](../../PROJECT_SPEC.md#1-项目目标)。
- **【用户明确确认】** 常规接待阶段，Agent 只生成回复建议，不决定是否发送；运营审核通过并主动点击发送后，系统才通过渠道发送。Agent 具备渠道发送能力不意味着它可自主决定或自主发送。来源：当前对话确认；相关原始基线见 [`PROJECT_SPEC.md §5.3`](../../PROJECT_SPEC.md#53-建议回复与人工审核)、[`docs/architecture.md §2`](../architecture.md#2-系统目标与边界)。
- **【用户明确确认】** 对已有负责业务员的客户，项目系统不承接该客户的消息处理或发送；业务员在本项目之外通过 WhatsApp、微信或邮件联系客户。来源：当前对话确认；相关原始基线见 [`PROJECT_SPEC.md §7.1`](../../PROJECT_SPEC.md#71-运营转交业务)。

## 2. 本次范围内

### 2.1 渠道与抓取安排

- **【用户明确确认】** 当前渠道为 WhatsApp、Gmail 和 Outlook；三个渠道需要抽象统一输入/输出，形成统一渠道接入规范。项目完成目标是真实接口接入；模拟链路仅用于功能测试，Token/API 在实际开发的 MVP 验证阶段准备。来源：当前对话确认；相关原始基线见 [`PROJECT_SPEC.md §4.1`](../../PROJECT_SPEC.md#41-渠道)。
- **【用户明确确认】** 邮箱和 WhatsApp 按 UTC+8 运行，工作日抓取时点为 08:00、09:30、11:00、14:00、15:30、17:00；不包含 12:00、18:00。星期日及中国大陆法定节假日不抓取，管理员可修改安排。每次处理未读信息，静默时段不代表已处理。来源：当前对话确认；相关原始基线见 [`PROJECT_SPEC.md §4.2`](../../PROJECT_SPEC.md#42-邮箱抓取时间)。

### 2.1 常规客户接待

- **【原始基线】** 对进入常规接待的消息，系统提供消息收集、Agent 意图分析及授权资料检索、回复建议，以及运营审核、编辑、忽略或主动发送的能力方向。建议回复使用与客户消息相同的语言，并向运营展示中文翻译。来源：[`PROJECT_SPEC.md §4`](../../PROJECT_SPEC.md#4-渠道与消息处理)、[`§5`](../../PROJECT_SPEC.md#5-运营接待闭环)、[`§6.1–§6.2`](../../PROJECT_SPEC.md#6-agent知识检索与外部信息)。
- **【用户明确确认】** Agent 仅生成建议，不决定发送；运营审核通过并主动点击发送后才通过项目接入渠道发送。来源：当前对话确认；原始人工审核基线见 [`PROJECT_SPEC.md §5.3`](../../PROJECT_SPEC.md#53-建议回复与人工审核)。
- **【用户明确确认】** 一旦客户链路已有负责该客户的业务员，Agent 完全不介入该客户消息，不分析、不生成回复建议、不发送；运营也不通过本项目处理或发送这类消息。业务员在项目外联系客户。来源：当前对话确认；原始业务员联系边界见 [`PROJECT_SPEC.md §7.1`](../../PROJECT_SPEC.md#71-运营转交业务)。

### 2.2 客户链路中的资料记录

- **【用户明确确认】** 员工可在系统中录入生产、库存相关的基本资料；采购部门可在客户当前链路中录入发货信息，包括物流单号和快递公司，或货拉拉及司机电话。此处是内部信息记录，不是外部物流查询或部门作业流程。来源：当前对话确认；相关原始资料上传基线见 [`PROJECT_SPEC.md §3`](../../PROJECT_SPEC.md#3-用户与角色)、[`§6.2`](../../PROJECT_SPEC.md#62-知识资料)、[`§7.2`](../../PROJECT_SPEC.md#72-成交后工程与生产)。
- **【用户明确确认】** 工程、采购、生产等部门的内部操作不属于本项目开发和实现范围；相关部门返回任务名称和时间周期，本项目只记录这些信息，不实现部门内部操作流程。来源：当前对话确认；相关原始业务方向见 [`PROJECT_SPEC.md §7.2`](../../PROJECT_SPEC.md#72-成交后工程与生产)。

## 3. 非目标

- **【原始基线】** 不开发官网 AI 对话窗口或面向任意访客的聊天入口；Agent 不负责业务员接手后的持续客户跟进。来源：[`PROJECT_SPEC.md §1`](../../PROJECT_SPEC.md#1-项目目标)、[`§15`](../../PROJECT_SPEC.md#15-明确排除)。
- **【用户明确确认】** 对已有负责业务员的客户，不由本项目内 Agent、运营或业务员处理消息或发送回复；业务员通过项目外的 WhatsApp、微信或邮件联系客户。来源：当前对话确认。
- **【用户明确确认】** Agent 不通过网络搜索物流或库存信息来回复客户；本草稿不把外部物流查询作为本次能力。来源：当前对话确认；外部系统集成的原始 P2 分类见 [`PROJECT_SPEC.md §13 P2`](../../PROJECT_SPEC.md#13-优先级范围)。
- **【用户明确确认】** 本次不实现外部生产、库存、物流系统集成；保留后续扩展空间。来源：当前对话确认；原始 P2 列表见 [`PROJECT_SPEC.md §13 P2`](../../PROJECT_SPEC.md#13-优先级范围)。
- **【用户明确确认】** 原始基线中扩展类 P2 能力不纳入本次开发，但保留扩展空间；其中明确包括合同 OCR、生产/库存/物流外部系统集成、更多渠道扩展。来源：当前对话确认；分类见 [`PROJECT_SPEC.md §13 P2`](../../PROJECT_SPEC.md#13-优先级范围)。
- **【范围边界】** 合同扫描件上传（如纳入成交资料记录）与合同 OCR/内容解析是不同能力；本次排除 OCR 不等于自动排除已提出的资料上传。上传内容及可见范围仍须按已确认范围和待确认事项处理。来源：[`PROJECT_SPEC.md §6.2`](../../PROJECT_SPEC.md#62-知识资料)、[`§7.2`](../../PROJECT_SPEC.md#72-成交后工程与生产)、[`§13 P2`](../../PROJECT_SPEC.md#13-优先级范围)。

## 4. 范围边界

### 4.1 业务员负责客户与常规接待的分界

- **【用户明确确认】** 常规接待路径：Agent 生成回复建议；运营审核并主动点击发送后，项目系统经已接入渠道发送。
- **【用户明确确认】** 客户链路已有负责业务员：Agent 完全不介入、不生成建议；项目系统不处理或发送该类客户消息；业务员在项目外联系客户。
- **【范围边界】** 发货记录是客户链路中的内部记录，不表示项目系统接管业务员的客户沟通，也不表示系统查询外部物流状态。

以上三项来源：当前对话确认；常规接待及转交原始背景见 [`PROJECT_SPEC.md §5.3`](../../PROJECT_SPEC.md#53-建议回复与人工审核)、[`§7.1`](../../PROJECT_SPEC.md#71-运营转交业务)。

### 4.2 部门信息记录与部门内部操作的分界

- **【用户明确确认】** 项目只记录相关部门返回的任务名称和时间周期；员工可以录入生产、库存基本资料，采购可以将发货信息录入客户链路。
- **【用户明确确认】** 不开发或实现工程、采购、生产等部门的内部操作流程。
- **【范围边界】** 内部记录能力不等于生产审核、生产排班、工程设计、采购作业、物流状态追踪或相应外部系统集成。

来源：当前对话确认；现有规格中关于成交后流程的原始描述见 [`PROJECT_SPEC.md §7.2`](../../PROJECT_SPEC.md#72-成交后工程与生产)，其细节原本标为待确认。

### 4.3 P2 扩展能力与本次范围的分界

- **【原始基线】** 合同 OCR、生产/库存/物流外部系统集成及更多渠道扩展列为 P2 后续项。来源：[`PROJECT_SPEC.md §13 P2`](../../PROJECT_SPEC.md#13-优先级范围)。
- **【用户明确确认】** 上述扩展类能力不纳入本次开发，保留后续扩展空间。当前允许的内部资料录入与客户链路发货信息记录，不应与外部集成混为一谈。来源：当前对话确认。
- **【建议】** 后续如讨论扩展能力，应另行确认其范围；本草稿不将“预留扩展空间”解释为本次实现接口、集成或 OCR。

3. **【待我确认】统一渠道输入/输出规范的字段细节：** 三个真实接口的统一映射以实际 MVP 验证结果为依据，当前不预设字段或最终接口合同。来源：当前对话确认；原始接入要求见 [`PROJECT_SPEC.md §4.3`](../../PROJECT_SPEC.md#43-消息接收与存储)、[`§9.2`](../../PROJECT_SPEC.md#92-原基线接口规划)。
